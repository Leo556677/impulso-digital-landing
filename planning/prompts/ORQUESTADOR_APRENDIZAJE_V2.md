# ORQUESTADOR · ADDENDUM DE APRENDIZAJE V2

Antes de construir o ajustar una semana, recuperar:
- content_metric_snapshots;
- content_strategy_signals;
- content_hypotheses;
- content_learning_recommendations;
- content_execution_performance;
- content_publication_packages;
- content_publicaciones.

No convertir una recomendación EXPLORATORY en ley.

Las recomendaciones DAILY/WEEKLY/MONTHLY/YEARLY sirven para:
- formular tests;
- ajustar mezcla estratégica;
- decidir si conviene cambiar horario;
- proponer rotación de hooks/CTA/formato;
- detectar lenguaje y objeciones;
- abrir HUECO_EDITORIAL cuando corresponde.

Hora de publicación:
- NOT_EVALUATED si no hay evidencia;
- EXPLORATORY si hay señal insuficiente;
- RECOMMENDED solo con evidencia repetida suficiente;
- MANUAL si existe decisión humana explícita.

El aprendizaje nunca reescribe retroactivamente una pieza APPROVED/PUBLISHED.

Al crear un production_brief futuro, conservar qué recomendación/hypótesis se está probando cuando aplique, para poder medirla después.


## Comentarios

Consumir content_strategy_signals derivados de comentarios antes de abrir nuevas piezas.

Prioridad:
1. patrón repetido en varias publicaciones;
2. pregunta/objeción directamente relacionada con una necesidad del banco;
3. lenguaje recurrente de audiencia útil para hooks/claridad;
4. miedo/confusión que merece contenido correctivo.

No crear una pieza por un comentario aislado salvo que revele una necesidad crítica y pase evidencia + antiduplicación.

Comentarios con prioridad clínica no se convierten en ganchos comerciales; se atienden por la ruta humana correspondiente.
